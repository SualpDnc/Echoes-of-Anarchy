# Echoes of Anarchy — notes for AI coding agents

These notes are for any agent working on this project (Claude Code, Codex, ...). Read `docs/DESIGN.md` first:
it records the story, the decisions already made with the owner, and the phase plan with its status.

## Working with the owner
- **Talk to the owner in Turkish.** The game's own text is English; subtitles show either English or Turkish (one language, chosen by the player).
- Work one phase at a time. At the end of a phase, explain how to test it (menu path, keys) and wait for the owner to test it before starting the next one.
- Do not overturn decisions already in `docs/DESIGN.md`. If one needs to change, ask.
- Owner feedback so far: no on-screen threat-direction arcs (removed by request); health must be visible (VITALS bar); every melee strike needs a visible animation. The camera must not tremble or bob too much; keep the handheld/breathing noise subtle (see the camera jitter entry in `docs/CHANGELOG.md`). The owner liked the phase 5 characters.
- Owner feedback on 6b: Dispatch's radio voice sounds good and Mia's is OK, but direct babble (Daniel, Luis) sounded very synthetic: keep dialogue low in the mix and run direct voices through the room channel. Characters seen up close need real faces. The way forward must be obvious (no waypoint markers: in-world cues plus the HDG/objective lines). Choices must have visible consequences. More stamina (now 15 s). Reloads must be seen and heard. Distant sirens must fade with distance.
- The owner wants a **clean image**: no heavy grain, scanlines or chromatic aberration, and streets that are readable rather than very dark.

## Handoff rule: leave the project ready for the next agent
The owner switches between agents (Claude Code, Codex, ...). Another agent with **no memory of your session** must be able to continue from the repo alone. Before you finish any piece of work:
1. Update `docs/DESIGN.md`: the phase table (status), and any new decision made with the owner, with the reason behind it.
2. Update this file: new classes and folders in the code layout table, new menus or keys, new gotchas, and owner feedback (likes and dislikes).
3. Add a short entry to `docs/CHANGELOG.md` (newest first): date, the agent's name, what changed, what the owner still needs to test, and any known issues.
4. Make sure the code compiles (see "Checking your work").
5. Commit (only once the owner approves): a message that says what changed and why.
Do not keep important knowledge only in your own memory or chat; if it isn't in the repo, the next agent won't know it.

## Core rule: everything is generated by code
No imported models, textures or audio. New content goes into generators (C#), shaders (HLSL) or synthesis recipes.

## Unity setup
- Unity **6000.6.2f1** (Unity 6.6) with URP 17.6 (PC renderer, Forward+, SSAO) and **Input System only** (the old Input Manager is off).
- Packages in use: AI Navigation (NavMeshSurface), UGUI, Timeline (not used yet).

## How the scene is made
- **Tools > Echoes > Build Harlow District** (`Assets/_Game/Scripts/Editor/EchoesSceneBuilder.cs`) creates the whole playable scene from scratch:
  textures and materials (via `MaterialLibrary`), the district, player, systems, reflection-probe bake and reverb zones.
- `Assets/_Game/Generated/` and `Assets/_Game/Scenes/` are **build outputs** and are git-ignored. After a fresh clone, run the menu.
- **Tools > Echoes > Regenerate Textures** forces texture synthesis to run again. Textures are otherwise cached as PNGs.
- To add something to the world, change the generators and rebuild. Never hand-edit the generated scene.

## Conventions and gotchas (learned the hard way)
- **Match the existing style:** XML `<summary>` on classes, short comments that explain why, `[Header]` groups, singletons as `static Instance` set in `Awake` and cleared in `OnDestroy`.
- **One MonoBehaviour per file, and the file name must equal the class name**, or Unity can't serialize it into the scene.
- **Never use `?.` or `??` on UnityEngine.Object** (fake-null). Use `TryGetComponent` or explicit `!= null`.
- **Mesh winding:** Unity is left-handed and front faces wind clockwise. `MeshBuilder.Quad(a,b,c,d)` takes bottom-left, bottom-right, top-right, top-left as seen from the front. Check normals whenever you add a primitive.
- **MeshBuilder UVs are in metres.** A material's tiling = 1 / tile size in metres (see `MaterialLibrary.Pbr`).
- **Texture recipes write albedo and emission as linear values.** `MaterialLibrary.Save` gamma-encodes them for sRGB import. Masks (R metal, G occlusion, A smoothness) and normals stay linear.
- **Synth recipes (`DSP`, `SynthLibrary`) must stay pure C#:** System.Math only, no UnityEngine. They run in `Parallel.For` and can be rendered offline.
- Clips and some textures exist only at runtime, so components store a `SoundId` or regenerate in `Awake`/`OnEnable`.
- On the very first Play after a rebuild, the screen can show cyan for a few seconds. This is the editor's async shader compilation, not a bug (a shader warm-up is planned for phase 7).
- Keep shadowed lights scarce (one street lamp in three; barrel fires cast no shadows). Point-light shadows cost 6 renders each.
- **Dialogue text lives in `DemoLines`** (English voice text + Turkish subtitle per line). The game's English is the voice text; always write both. Voices are babble (`SynthLibraryVoice`: 24 syllables per speaker); there are no real words to sync.
- New `SoundId`s go at the **end** of the enum. The bank seeds each recipe from its enum value, so inserting in the middle changes how every later sound renders.
- Before 19:00 `PurgeClock` turns `DistantEvents.purgeActive` off (a quiet city). Use F6 to jump to 18:59:50.
- New `Speaker`s and `SoundId`s go at the end (`Speaker.LuisRadio` uses `SoundId.VoiceLuisRadio`, Luis's voice baked through the radio band: a voice's channel is baked into its clips, so a speaker heard over a different channel needs its own voice).
- **The demo starts in the ambulance.** Pressing Play runs the cold open (about 70 s to the crash). F4 skips to the crash site; for free testing set `DemoDirector.startAt` on the "Demo" object to `CrashSite` or `Sandbox` (Sandbox = the old spawn at the south end, no story). F6 during the ride breaks its timing.
- **Story vehicles, Luis, the Smiler watchers and med kits are built at runtime** by the sequences (like NPCs), not by the scene builder. The crash-site layout (rest poses, Luis's spot, the spilled kits, the wake point) lives in `ColdOpenSequence`. The old `Smilers_Intersection` test spawner was removed (the watchers replace it); the other test encounters stay until 6c.
- **Static field initialisers run in textual order.** A `static readonly` array that uses another static field must be declared after it (`ColdOpenSequence.CrashPoint` sits above the routes for this reason).
- **Seated or mounted player:** `CameraRig.Mount` disables `FPSController` and the `CharacterController` and moves the player with the seat every LateUpdate (even with the cursor free). Always `Unmount` before `FPSController.Teleport`.
- Vehicle glass uses `RuntimeMaterials.Glass` (URP Lit switched to transparent at runtime). The editor compiles the variant on demand; a player build may strip it (phase 7: keep the variant, e.g. with a saved glass material).
- When editing C# with perl one-liners, `$"` (interpolated strings) gets eaten by perl. Prefer the Edit tool for lines with `$"`.
- Use `FPSController.IsGrounded` (debounced) rather than `CharacterController.isGrounded` (flickers for single frames) for anything gameplay- or camera-related. The step cycle (`StepIndex + StepPhase`) is continuous; don't recompute it from the current stride.
- **Characters are authored at 1.0 scale in rest space** (root at the feet, +Z forward, head bone at y 1.60) and scaled by `CharacterLook.height` at the end (`ScaleVertices`). Skinning bands use rest heights (`NeckY`, `ElbowY`, `KneeY`... in `HumanoidBuilder`): if you move a bone, move its constant too.
- `BodyProfile` angles: θ = π/2 is the front (+Z), −π/2 the back, 0 the character's right (+X). Later garment layers are outer layers; a garment edge becomes a double ring (a visible hem).
- `SkinnedBodyBuilder` fixes triangle winding per triangle from an outward hint, so new parts don't need hand-wound faces.
- Runtime normal maps are packed RGB with A = 1 in a linear `Texture2D`; URP's RG/AG unpack reads them correctly on PC.
- Foot IK raycasts ignore the character itself, `Hitbox` colliders, the player's CharacterController and loose rigidbodies. It is skipped beyond `ikDistance` (40 m) and fades out in Kneel/Cower.

## Checking your work
- When the Unity editor has the project open, batchmode can't run. To compile-check, copy `Assembly-CSharp.csproj` to a temp folder, make its `<HintPath>Library\...` entries absolute, replace the `<Compile>` items with every `Assets/_Game/Scripts/**/*.cs` file, and run `dotnet build`. Editor scripts compile in that same assembly.
- Audio recipes can be rendered to WAV with a small `net9.0` console project that includes only `DSP.cs` and `SynthLibrary.cs`. Check for NaN, silence and peak levels.
- Python is not installed on the dev machine. Use PowerShell or bash.
- Shaders are only compiled inside Unity, so ask the owner to check the Console after a rebuild.
